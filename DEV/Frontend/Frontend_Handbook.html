    How the web works the base for everything

    Every page you build is delivered the same way. Knowing the delivery route makes the rest easier to place.

    Request and response

    The browser is the client. It asks a server for something over HTTP, and the server answers. HTTPS is the same thing with encryption. Every click that loads data is a request.

    What happens when you open a URL

    1. DNS turns example.com into an IP address.
    2. The browser connects and sends a request.
    3. The server replies with HTML.
    4. The browser reads the HTML and asks for the CSS, JS and images it mentions.
    5. The browser renders the page.

    Parts of a URL

    https://example.com:443/blog/5?sort=asc#intro
protocol  domain     port path  query    fragment

    Methods and status codes

    Methods say what you want: GET read, POST create, PUT/PATCH update, DELETE remove.

    Status codes say what happened: 200 ok, 201 created, 301 moved, 400 bad request, 401 not logged in, 403 forbidden, 404 not found, 500 server error.

    How the browser renders

    HTML becomes the DOM tree. CSS becomes a style tree. The browser combines them, works out sizes and positions (layout), then draws pixels (paint). Changing layout is more costly than changing color, which matters later for animations.

    Frontend and backend

    Frontend is the code that runs in the browser: what users see and click. Backend runs on a server: logic, storage and security. They talk through APIs. Someone who does both is a full-stack developer.

    Go deeperOpen DevTools, go to the Network tab, reload any site, and watch the requests happen. Then read MDN: An overview of HTTP. The Backend handbook's HTTP stage shows the server side.

    HTML structure

    HTML says what is on the page: headings, paragraphs, images, links, forms. It is a markup language with no logic, only structure.

    Elements and attributes

    An element is an opening tag, content, and a closing tag. Attributes add settings to the tag.

    <a href="/about" class="link">About</a>
<img src="cat.png" alt="A sleeping cat">

    Page skeleton

    <!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>My page</title>
    <link rel="stylesheet" href="style.css">
  </head>
  <body>...</body>
</html>

    The head holds things users do not see. The body holds what they do.

    Text, links and media

    h1 to h6 for headings (one h1 per page), p for paragraphs, strong and em for emphasis, a for links, img, video and audio for media.

    Lists and tables

    ul is a bullet list, ol is numbered, each item is an li. Tables use table, tr for rows, th and td for cells. Use tables for data, never for page layout.

    Forms

    Forms are how users send data. Each input needs a name and a matching label.

    <form action="/signup" method="post">
  <label for="email">Email</label>
  <input id="email" name="email" type="email" required>
  <button type="submit">Sign up</button>
</form>

    Other inputs: text, password, checkbox, radio, textarea, select.

    The browser checks required, minlength, pattern and type="email" before the form submits. That check is only for convenience, because the server must validate everything again.

    Semantic HTML

    Use tags that describe meaning: header, nav, main, section, article, aside, footer. Search engines and screen readers use them to understand the page. A pile of divs tells them nothing.

    Block and inline, id and class

    Block elements (div, p) take a full row. Inline elements (span, a) sit inside a line of text. An id must be unique on the page. A class can be reused anywhere, and it is what CSS mostly targets.

    Accessibility

    Write alt text for images, connect labels to inputs, keep headings in order, make everything reachable by keyboard, and keep enough color contrast. Reach for aria-* attributes only when no plain tag does the job.

    Go deeperKeep MDN's HTML elements reference open and build one small page using only semantic tags.

    CSS basics style

    CSS controls how HTML looks: color, fonts, spacing and layout. A rule is a selector that picks elements and a list of property: value pairs.

    Three ways to add CSS

    Inline with style="", internal in a <style> tag, or external in a .css file linked from the head. External is the normal choice because many pages can share one file.

    Selectors

    p { }              /* every p */
.card { }          /* class="card" */
#header { }        /* id="header" */
nav a { }          /* any a inside nav */
ul > li { }        /* direct children only */
a:hover { }        /* pseudo-class: a state */
p::first-line { }  /* pseudo-element: a part */

    Cascade and specificity

    When two rules hit the same element, the more specific selector wins: inline, then id, then class, then tag. If they tie, the later rule wins. !important beats everything and usually causes trouble later. Some properties, like color and font-family, are inherited by children.

    The box model

    Every element is a box with four layers, from inside out: content, padding, border, margin. Most layout confusion comes from forgetting this. Set box-sizing: border-box so a width includes padding and border. Try it:

    content

    Dashed line is the margin edge, thick line is the border, grey fill is the padding.

    Units

    px is fixed. % is relative to the parent. em and rem scale with font size, and rem is the safer one. vw and vh are percentages of the screen width and height.

    Colors and typography

    Colors come as hex (#fffaf0), rgb() or hsl(). For text, learn font-family, font-size, font-weight, line-height and letter-spacing. A line-height of 1.5 to 1.7 reads well.

    Backgrounds, borders and shadows

    background, border, border-radius for rounded corners, box-shadow for depth, and overflow to decide what happens when content spills out of its box.

    CSS variables

    :root { --brand: #0a0a0a; --gap: 16px; }
.card { background: var(--brand); padding: var(--gap); }

    Define a value once, reuse it everywhere. This page switches between dark and light by redefining a handful of variables.

    Go deeperWork through MDN's CSS building blocks. Then rebuild a simple landing page and edit its CSS live in DevTools to watch the cascade.

    CSS layout placing things

    Once boxes look right, you arrange them. Modern layout is mostly flexbox, grid, and media queries.

    display

    block takes a full row, inline flows in text, inline-block flows but accepts width and height, none removes the element. flex and grid turn an element into a layout container.

    position and z-index

    position: static;    /* default, normal flow */
position: relative;  /* offset from its own spot */
position: absolute;  /* placed inside nearest positioned parent */
position: fixed;     /* stuck to the screen */
position: sticky;    /* normal, then sticks while scrolling */

    z-index decides which overlapping element sits on top.

    Flexbox

    Flexbox lays items out along one direction, a row or a column. It handles alignment, spacing and centering with very little code. Use it for navbars, button groups and card rows.

    1
    2
    3

    Grid

    Grid arranges items in rows and columns at once. Use it for page layouts and galleries.

    .gallery {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 16px;
}

    Rule of thumb: flexbox for one direction, grid for two.

    Responsive design

    The same page has to work on a phone, a tablet and a desktop. You need the viewport meta tag, flexible units, and media queries. Start from the phone layout and add rules for larger screens (mobile-first).

    .cards { display: grid; gap: 16px; grid-template-columns: 1fr; }
@media (min-width: 768px) {
  .cards { grid-template-columns: repeat(3, 1fr); }
}

    clamp(16px, 2.5vw, 22px) gives a size that grows with the screen but never goes below the minimum or above the maximum. Heading sizes are the usual use.

    Centering, the common recipe

    .parent {
  display: flex;
  justify-content: center;
  align-items: center;
  min-height: 100vh;
}

    Go deeperFlexbox Froggy and Grid Garden are short games that teach both. Then rebuild a pricing-card page that works at phone width.

    Transforms and motion movement

    Transforms move, rotate and scale an element. Transitions and animations spread a change over time.

    transform

    translate moves, rotate turns, scale resizes, skew slants. A transform does not change the layout, so neighboring elements stay where they are. The dashed box below is the original position. Order matters, because each step happens in the already transformed space.

    box

    transition

    Tells the browser to animate a property change instead of jumping. You give it the property, duration, easing and optional delay.

    .btn { transition: transform 200ms ease, background 200ms ease; }
.btn:hover { transform: translateY(-2px); }

    @keyframes and animation

    When you need more than a start and an end, or something that loops, describe the steps in @keyframes and attach them with animation.

    @keyframes pulse { from { opacity: 1 } to { opacity: .4 } }
.dot { animation: pulse 1s ease-in-out infinite alternate; }

    Keeping it smooth

    Animate transform and opacity. They run on the GPU and skip layout. Animating width, height, top or left forces layout on every frame and can stutter.

    3D basics

    Add perspective to a parent and use rotateX or rotateY on the child for card flips and tilt effects.

    Reduced motion

    Some people get dizzy from animation. Wrap big motion in @media (prefers-reduced-motion: no-preference), or switch it off inside prefers-reduced-motion: reduce.

    Go deeperRead MDN: Using CSS transitions, then build a card that lifts on hover and a loading spinner using only CSS.

    JavaScript behavior

    JavaScript is the programming language of the browser. It reacts to clicks, checks forms, fetches data and changes the page without a reload. It also runs on servers through Node.js.

    Variables and types

    Use const by default and let when the value changes. Skip var. Types are string, number, boolean, null, undefined, object and array. Compare with ===, not ==.

    Functions

    Functions are values. You can store them, pass them in, and return them. Arrow functions are the short form.

    function add(a, b) { return a + b; }
const add2 = (a, b) => a + b;

    Arrays and objects

    Your two main data structures. The array methods below show up in nearly every project.

    const nums = [1, 2, 3, 4];
nums.map(n => n * 2);               // [2, 4, 6, 8]
nums.filter(n => n % 2 === 0);      // [2, 4]
nums.reduce((sum, n) => sum + n, 0); // 10
nums.find(n => n > 2);              // 3

    Control flow

    if / else, switch, and loops: for, while, for...of. Falsy values (0, "", null, undefined, NaN, false) count as false in a condition.

    Scope and closures

    Variables are visible only inside the block or function that declares them. A closure is a function that remembers the variables around where it was made.

    function counter() { let c = 0; return () => ++c; }
const next = counter();
next(); // 1
next(); // 2

    Why it matters. Closures give you private data: nothing outside counter can touch c. They let an event handler remember which item it was created for. Every React hook depends on them. They also cause the "stale closure" bug, where a function created during an old render still sees old values. If a timer inside useEffect keeps printing an old count, this is why.

    Modern syntax (ES6+)

    const { name, age } = user;            // destructuring
const all = [...a, ...b];              // spread
const city = user?.address?.city;      // optional chaining
console.log(`Hi ${name}`);             // template string
import { add } from "./math.js";       // modules

    The this keyword

    this is decided when a function is called, not where it is written. The rules:

    • obj.method(): this is obj.
    • A plain call fn(): undefined in modules and strict mode.
    • Arrow functions have no this of their own. They use the one from the code around them.
    • A normal-function event listener: this is the element.
    • bind, call and apply set it by hand.
    const user = {
  name: "Eswar",
  hi() { return this.name; },
  later() { setTimeout(() => console.log(this.name), 100); },
};
user.hi();                    // "Eswar"
const f = user.hi; f();       // error: this is undefined
user.hi.bind(user)();         // "Eswar"
user.later();                 // "Eswar", the arrow keeps this

    The classic bug is passing user.hi as a callback and losing this. An arrow function or bind fixes it.

    Classes

    class is a cleaner way to write object blueprints with a constructor, methods and extends, built on prototypes underneath. You will see classes in older React code, in Node libraries and in custom error types. Modern React uses functions instead.

    Errors and JSON

    try / catch handles errors without crashing. JSON is the text format for sending data between frontend and backend.

    const text = JSON.stringify({ name: "Dinesh" });
const obj = JSON.parse(text);

    Go deeperPart 1 of javascript.info covers this stage and is the clearest free course. Solve a few array problems with map and filter before moving on.

    The DOM JavaScript meets the page

    The browser turns your HTML into a live tree of objects. JavaScript can read that tree and change it, and the screen updates.

    What the DOM is

    The DOM is not your HTML file. The file is the starting blueprint, and the DOM is the living copy in memory. The DOM is a browser API, reached through the global document object, and is not part of the JavaScript language itself.

    document
└── html
    └── body
        ├── h1#title   "Hello"
        └── button.btn "Click"

    Longer notes are in DOM/DOM_Notes.md.

    Selecting elements

    document.getElementById("title");
document.querySelector(".card");        // first match
document.querySelectorAll("li");        // all matches

    querySelector takes any CSS selector, so it is the one to learn first.

    Changing elements

    const title = document.querySelector("#title");
title.textContent = "Hello";
title.classList.add("active");
title.setAttribute("data-id", "5");
title.style.color = "red";

    Prefer textContent over innerHTML for user text. innerHTML parses HTML, so untrusted input can inject scripts (XSS).

    Creating and removing

    const li = document.createElement("li");
li.textContent = "New item";
document.querySelector("ul").append(li);
li.remove();

    Events

    Things that happen on the page: click, input, submit, keydown. You attach a listener, and the browser passes an event object.

    btn.addEventListener("click", (e) => {
  console.log(e.target);
});
form.addEventListener("submit", (e) => {
  e.preventDefault();   // stop the page reload
});

    Bubbling and delegation

    An event does not stay on the element you clicked. It bubbles up through every parent. That is why one listener on a list can handle clicks on all its items, which is called event delegation. Click the inner box:

    outer
    middle
    inner
    Click a box to see the order.
    list.addEventListener("click", (e) => {
  const item = e.target.closest("li");
  if (item) item.classList.toggle("done");
});

    Debounce and throttle

    Some events fire dozens of times a second: input, scroll, resize. Running heavy work on each one makes the page lag and floods the server.

    • Debounce waits until the events stop for a moment, then runs once. Use it for search-as-you-type, so typing "react" sends one request instead of five.
    • Throttle runs at most once per interval while events keep coming. Use it for scroll position or infinite scroll.
    function debounce(fn, ms) {
  let t;
  return (...args) => {
    clearTimeout(t);
    t = setTimeout(() => fn(...args), ms);
  };
}
input.addEventListener("input", debounce(search, 300));

    This is a closure at work: t survives between calls.

    Moving around the tree

    parentElement, children, nextElementSibling and closest() let you go from one element to its relatives.

    Browser storage

    localStorage.setItem("theme", "dark");
localStorage.getItem("theme");   // "dark"

    Values are always strings, so use JSON.stringify for objects. localStorage survives a restart, sessionStorage is cleared when the tab closes, and cookies are also sent to the server. For login tokens, read where the browser should keep the token before reaching for localStorage.

    Async JS and fetch talking to servers

    Network calls take time. Asynchronous code lets the page stay responsive while it waits.

    The event loop

    JavaScript does one thing at a time. When it starts something slow, like a request or a timer, it hands the job to the browser and keeps going. When the job finishes, the callback joins a queue and runs when the main code is free. Think of a waiter who takes your order and serves other tables while the kitchen cooks.

    Node.js runs the same loop on the server. The Backend handbook has a live demo of the order that callbacks run in.

    Callbacks, promises, async/await

    Callbacks came first and nested badly. Promises fixed that with .then(). async/await reads like normal top-to-bottom code and is what you should write.

    // promise style
fetch("/api/users")
  .then(r => r.json())
  .then(users => console.log(users))
  .catch(err => console.error(err));
    // async/await, same thing
async function load() {
  try {
    const res = await fetch("/api/users");
    if (!res.ok) throw new Error(res.status);
    const users = await res.json();
  } catch (err) {
    // show an error message
  }
}

    Running requests in parallel

    // one after another: about 2 seconds
const user = await getUser();
const posts = await getPosts();

// at the same time: about 1 second
const [u, p] = await Promise.all([getUser(), getPosts()]);
    • Promise.all fails as soon as one promise fails.
    • Promise.allSettled waits for every promise and reports each result, success or failure.
    • Promise.race settles with whichever finishes first. Racing a request against a timer gives you a timeout.

    Only run requests in parallel when neither needs the other's result.

    fetch

    fetch sends HTTP requests from the browser. For a POST, send JSON in the body and say so in the headers.

    await fetch("/api/tasks", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ title: "Learn DOM" }),
});

    Working with APIs

    An API is a set of URLs that return data, usually JSON. In the UI you always handle three states: loading, success, error. CORS is a browser rule that blocks calls to another origin unless that server allows them. The fix belongs on the server, as the Backend handbook's CORS card explains. How to design the API's URLs is covered in its REST stage.

    Timers

    setTimeout(fn, ms) runs once later. setInterval(fn, ms) repeats until you call clearInterval. Always clear intervals you no longer need.

    Common mistakes

    • Forgetting await, so you hold a promise instead of data.
    • Not checking res.ok. A 404 does not throw.
    • No error handling, so the UI hangs on "loading".

    Go deeperRead javascript.info: Promises, async/await. Then build a weather app on Open-Meteo (free, no API key) with loading and error states.

    Tooling the workshop

    The tools you use every day while building. None of them is hard, but React and Next.js assume you know them.

    Browser DevTools

    Press F12. Elements shows the live DOM and CSS. Console shows logs and errors. Network shows every request. Application shows storage. Lighthouse scores speed and accessibility.

    Git and GitHub

    Git keeps the history of your code. Learn: commit, branch, merge, pull, push, pull request, merge conflict. GitHub hosts the repo online. In this repo the habit is simple: pull before you start, push when you finish.

    Terminal basics

    cd to move, ls (or dir) to list, mkdir to make a folder. Most tools below are run from here.

    npm and package.json

    npm downloads libraries. package.json lists what the project needs and the scripts to run it. Libraries land in node_modules, which you never commit.

    npm install
npm run dev

    Vite and bundlers

    A bundler combines many source files into a few the browser can load, and a dev server reloads the page as you save. Vite is the common choice for React: npm create vite@latest.

    ESLint and Prettier

    ESLint flags likely mistakes. Prettier formats code the same way every time, which stops style arguments between two people sharing a repo.

    Environment variables

    Secrets and config like API keys live in a .env file that is ignored by Git. Anything shipped to the browser is public, so never put a real secret in frontend code.

    React components, props, state

    Plain DOM code gets messy as pages grow. React lets you describe what the UI should look like for the current data, and it updates the DOM for you.

    The core idea

    UI is a function of state. Change the data, and React redraws the parts that depend on it.

    You stop writing "find this element and change its text". You write what the screen should show, and update the data.

    Components

    A component is a function that returns markup. Names start with a capital letter. A page is a tree of components, such as Navbar, ProductCard and Footer, each reusable.

    JSX

    JSX is HTML-like syntax written inside JavaScript. Curly braces drop in any JS expression.

    • Return one root element, or wrap in <>...</>.
    • Write className, not class.
    • Attributes are camelCase, like onClick.
    • Close every tag, including <img />.

    Props

    Props are inputs a parent passes to a child, like function arguments. A child cannot change its props. The special prop children holds whatever sits between the tags.

    function Card({ title, children }) {
  return (
    <div className="card">
      <h3>{title}</h3>
      {children}
    </div>
  );
}

<Card title="Hello"><p>Body text</p></Card>

    State

    State is data a component owns and can change. When you call the setter, React re-renders. Never edit state directly, always make a new value.

    import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);
  return (
    <button onClick={() => setCount(count + 1)}>
      Clicked {count}
    </button>
  );
}

    Events and forms

    Handlers are props like onClick and onChange. A controlled input keeps its value in state, so the state is the single source of truth.

    <input value={name} onChange={e => setName(e.target.value)} />

    Conditional rendering and lists

    {tasks.length === 0 ? (
  <p>No tasks yet</p>
) : (
  <ul>
    {tasks.map(t => <li key={t.id}>{t.title}</li>)}
  </ul>
)}

    Each list item needs a stable, unique key, so React can tell items apart when the list changes.

    One-way data flow

    Data goes down through props. Changes go up through functions passed as props. When two components need the same data, move the state to their nearest common parent. This is called lifting state up.

    Routing

    React Router gives one page many URLs without reloading, which makes it a single page app (SPA). Clicking a link swaps components instead of downloading a new HTML page. Next.js replaces this with file-based routing.

    Styling with Tailwind CSS

    Tailwind is a CSS framework made of small utility classes, each doing one job. You style in the markup without inventing class names.

    <button className="rounded-lg bg-black px-4 py-2 text-white
                   hover:bg-gray-800 md:px-6">
  Save
</button>

    px-4 is horizontal padding, hover: applies on hover, and md: applies from medium screens up. Everything from the CSS stages still applies, because Tailwind is shorthand for it. Other options: plain CSS files, CSS Modules (class names scoped to one component), and component kits like shadcn/ui built on Tailwind.

    Go deeperRead react.dev/learn through "Managing State", then build a to-do list and a movie search.

    React hooks giving components abilities

    Hooks are functions that start with use. They let a function component hold state, run side effects, and share logic.

    The two rules

    • Call hooks at the top level of a component, never inside an if, loop or nested function.
    • Call them only from components or from your own hooks.

    React tracks hooks by call order, so the order must never change.

    useState

    Local data that triggers a re-render when it changes. It returns the value and a setter. For arrays and objects, copy then change: setItems([...items, newItem]).

    useEffect

    Runs code after the screen updates, for things outside React: fetching data, timers, event listeners. The dependency array decides when it re-runs.

    Dependency arrayEffect runs
    useEffect(fn)after every render
    useEffect(fn, [])once, after the first render
    useEffect(fn, [id])first render, then whenever id changes
     
    useEffect(() => {
  fetch("/api/users")
    .then(r => r.json())
    .then(setUsers);
}, []);
    useEffect(() => {
  const id = setInterval(tick, 1000);
  return () => clearInterval(id); // cleanup
}, []);

    Two traps. First, the user may leave the page before a fetch finishes. Create an AbortController, pass its signal to fetch, and call abort() in the cleanup so an old response never overwrites newer data. Second, an effect only sees the values from the render that created it (a closure). Leaving a variable out of the dependency array gives you stale data.

    useRef

    Holds a value that survives renders without causing one. The usual job is grabbing a DOM element.

    const inputRef = useRef(null);
<input ref={inputRef} />
<button onClick={() => inputRef.current.focus()}>Focus</button>

    useContext

    Shares data with many components without passing props through every level (prop drilling). Good for theme, current user, language.

    const ThemeContext = createContext("dark");
// wrap the tree: <ThemeContext.Provider value="light">
// any child:     const theme = useContext(ThemeContext);

    React.memo, useMemo and useCallback

    When a parent re-renders, React re-renders all its children too, even if their props did not change. That is usually cheap. When it is not:

    • React.memo(Component) skips a re-render when the props are the same as last time.
    • useMemo remembers a calculated value until its dependencies change.
    • useCallback remembers a function, so a memoized child does not receive a "new" function every render.
    const Row = React.memo(function Row({ item, onSelect }) { /* ... */ });

const sorted = useMemo(() => sortItems(items), [items]);
const onSelect = useCallback(id => setSelected(id), []);

    All three are speed tweaks. Measure with the React DevTools Profiler first. The React Compiler can add most of this automatically in newer setups.

    useReducer

    An alternative to useState when state has many related pieces. You send actions like "add" or "remove" to one function that decides the next state.

    Custom hooks

    Your own function starting with use that bundles other hooks, so logic can be reused.

    function useFetch(url) {
  const [data, setData] = useState(null);
  useEffect(() => {
    fetch(url).then(r => r.json()).then(setData);
  }, [url]);
  return data;
}

    Libraries built on hooks

    TanStack Query handles fetching, caching and loading states. Zustand and Redux Toolkit manage global state. Learn the built-in hooks first.

    Go deeperRead react.dev: Escape Hatches on refs and effects. Then build a stopwatch (needs useEffect cleanup) and a debounced search box that fetches as you type.

    JSX vs TSX adding types

    TSX is JSX written in TypeScript. The React you learned stays the same. You only add types.

    What TypeScript is

    JavaScript plus types that are checked before the code runs. It compiles down to plain JavaScript, so the browser never sees the types. You get autocomplete, and typos fail in your editor instead of in front of a user.

    function add(a: number, b: number): number { return a + b; }
add("1", 2);   // error while coding

    The difference

    .jsx.tsx
    LanguageJavaScript + markupTypeScript + markup
    TypesNoneYes, checked
    Markup like <div> allowedYesYes
    Runs in browser asJavaScriptThe same JavaScript, types removed

    A plain .ts file cannot contain markup, so any component with TypeScript goes in a .tsx file. Files with no markup, like utilities, stay .ts. Here is the same component both ways:

    // Card.jsx
function Card({ title, count = 0 }) {
  return <h3>{title} ({count})</h3>;

    Next.js React with everything included

    React is only a UI library. Next.js is a framework on top of it that adds routing, server rendering, and a backend in the same project.

    What it is and why it exists

    A plain React app sends an almost empty HTML page and builds the screen in the browser. The first load is slow and search engines see little. Next.js can build the HTML on the server, so users and crawlers get a finished page.

    Next.js also makes many decisions for you: how to route, fetch, optimize and deploy.

    File-based routing

    Folders are URLs. No router setup.

    app/
├── layout.tsx            shared navbar and footer
├── page.tsx              /
├── about/page.tsx        /about
├── blog/[id]/page.tsx    /blog/5   (dynamic)
└── api/users/route.ts    /api/users (backend)

    Rendering strategies

    The big idea in Next.js is choosing where and when the HTML is made.

    NameHTML is madeGood for
    SSR, server-side renderingon the server, per requestfresh data, dashboards, SEO
    SSG, static generationonce, at build timeblogs, docs, marketing pages
    ISR, incremental regenerationat build, then rebuilt on a timerstatic pages that change sometimes
    CSR, client-side renderingin the browser, like plain Reacthighly interactive widgets

    Server and client components

    Components are server components by default. They run on the server, can read a database or call an API directly, and send no JavaScript to the browser. Add "use client" at the top of a file when a component needs state, effects or browser events.

    // server component (default)
export default async function Page() {
  const res = await fetch("https://api.example.com/users");
  const users = await res.json();
  return <UserList users={users} />;
}
    "use client";   // client component
import { useState } from "react";

export function LikeButton() {
  const [n, setN] = useState(0);
  return <button onClick={() => setN(n + 1)}>{n}</button>;
}

    How frontend and backend meet

    Follow one click in a to-do app through the whole stack. Each step links to where it is explained.

    1. The user types a task and presses Add. A React event handler runs and updates state.
    2. The handler calls fetch("/api/tasks", { method: "POST" }) with the task as JSON.
    3. The request crosses the network as HTTP, and CORS applies if the API lives on another origin.
    4. Express runs its middleware: parse the JSON, check the login cookie, validate the body.
    5. A service saves the task in the database.
    6. The server replies 201 Created with the saved task.
    7. Back in the browser, the new task goes into state and React re-renders the list.

    With Next.js, steps 2 to 6 can shrink into one server action, but the same things still happen underneath.
