# Eswar's independent Split Expenses build

This folder is your implementation workspace for December 2026. Build the application from scratch here. Choose your own language, frameworks, database, and libraries, and keep your setup and run instructions in this README as the app grows.

## Start with the HTML guides

1. Open [Guidance.html](../../Guidance.html) in a browser. Read the starting plan and first-session sequence before setting up the app.
2. Open [Project_Guide.html](../../Project_Guide.html) in a second browser tab. Choose **Eswar** under **Learning as**.
3. Read the first stage, explain the Rs. 900 dinner calculation on paper, and record your stack choices in the stage notes.
4. Work through one stage at a time. Read its requirements, attempt the task, reveal hints gradually when needed, and perform the stated checks before ticking a box.
5. Use **Continue** to resume. Save doubts and decisions in the stage notes. Export your progress regularly; it lives in this browser, not in Git.

The HTML files are offline guides. If GitHub shows their source, pull or download the repo, find the files in `DEV/Projects/Split_Expenses/`, and open them locally with Edge, Chrome, or another browser. External reference links need internet access. Importing a workbook backup replaces both locally saved learner profiles, so export your own backup first.

## Your December agreement

- Write the application code yourself, including setup, features, fixes, and tests.
- Use AI only to understand a concept, clarify syntax, compare decisions, or ask for a small hint. Ask questions around your own attempt and explain what you learned afterward.
- Do not use AI to generate implementation files, complete features, large changes, or ready-to-paste solutions.
- Official documentation, the HTML hints, small experiments, and conversations with Dinesh are useful learning tools.

## Approximate effort

Budget **80–120 focused hours per person** for the complete workbook, including understanding, implementation, debugging, tests, and deployment. This is a planning estimate, not a deadline. It assumes basic HTML/CSS/JavaScript familiarity and some exposure to HTTP and databases; allow another **20–40 hours** if those foundations are new.

| Work | Approximate hours |
|---|---:|
| Requirements, tool decisions, and money rules | 5–7 |
| Screens, forms, and sample-data interface | 12–18 |
| Data model, setup, and persistence | 6–9 |
| Backend operations and balance calculations | 14–20 |
| Connecting frontend and backend | 6–9 |
| Authentication and permissions | 10–15 |
| Custom shares, safe edits, and settlements | 14–20 |
| Automated checks and browser verification | 9–12 |
| Deployment, run instructions, and demo | 4–6 |
| **Total of these ranges** | **80–116** |

For December's 31 days, **3 hours a day gives about 93 hours; 4 gives about 124 hours**. Leave room for missed days and difficult bugs. At 2 hours a day, expect to continue into January if you aim to finish every core stage.

## A practical work session

1. Pull the repo before starting and pick one unfinished workbook task.
2. Predict the expected behavior and write a small example.
3. Implement it yourself, run it, and inspect both a normal case and a failure case.
4. Mark only verified checks, record one lesson, and write the exact next action.
5. Review your own changes and make a small, clear commit when ready. Coordinate shared guide changes with Dinesh.

Your first working milestone is a group with three members, one equal-split dinner, persisted records, and correct balances after refresh. Finish that flow before adding the later features. The full finish line is the workbook's verification and deployment stages, plus being able to explain your decisions to Dinesh.
